# M0.8-A: Property Intelligence Engine

This milestone adds a small, deterministic risk-scoring domain. It is a
demonstration of how BOWERA can turn explicitly supplied property facts into a
repeatable assessment. It is not a financial, legal, compliance, or investment
recommendation, and it is not an API or an authorization boundary.

The implementation is in [`risk-engine.ts`](../../src/lib/intelligence/risk-engine.ts).
It has no React, database, HTTP, or language-model dependency. The future-facing
service and provider contracts are in [`ports.ts`](../../src/lib/intelligence/ports.ts).

## 1. What TypeScript is

TypeScript is JavaScript with a type system. JavaScript runs the application;
TypeScript helps us catch mismatched data and mistakes while we write and build
it. For example, the risk engine's input says that a lease expiry is either a
number of days or `null`:

```ts
leaseExpiryDays: number | null;
```

The `null` case is meaningful: it means the lease information is not available.
It must not be replaced with `0`, because zero means the lease expires today.

## 2. What a type and interface are

A type describes which values a variable or object may contain. An interface
describes the shape an object must have. The engine uses an interface so that
callers can see the complete input contract:

```ts
export interface RiskInput {
  readonly organizationId: string;
  readonly unitId: string;
  readonly isVacant: boolean | null;
  readonly leaseExpiryDays: number | null;
  readonly hasOutstandingMaintenance: boolean | null;
  readonly dataObservedAt: string;
}
```

`readonly` documents that these values are evidence supplied to the assessment,
not fields the engine should edit. TypeScript types disappear at runtime, so
the engine also validates values that arrive at runtime.

## 3. What a pure function is

A pure function depends only on its inputs and returns a result without changing
anything outside itself. `assessPropertyRisk` is pure: it does not read the
clock, call a service, write to a database, or modify the input. This makes it
safe to run in different application layers and easy to test.

The evaluation time is an explicit argument:

```ts
assessPropertyRisk(input, '2026-10-20T12:00:00Z');
```

If the same valid input and evaluation time are supplied again, the same
assessment is returned.

## 4. What an algorithm is

An algorithm is a defined set of steps for turning input into output. Risk v1
checks three fixed rules, adds the points for each triggered rule, and maps the
total to a priority. Its rule definitions and stable identifiers are kept
together in `RISK_RULES` rather than accepted from the caller.

## 5. What deterministic means

Deterministic means the same inputs produce the same outputs. The engine uses no
randomness, network data, model response, or implicit current time. It includes
the version (`risk-v1`), data observation time, and caller-supplied
`evaluatedAsOf` in every result so a later consumer can interpret what was
calculated and when.

## 6. Why input validation matters

Type annotations protect normal TypeScript call sites, but they do not validate
JSON, JavaScript callers, or data from a future service. The engine therefore
checks UUID-shaped organization and Unit identifiers, real timestamps,
boolean/null states, and safe integer day counts. It also rejects data observed
after the requested evaluation time. Errors use one generic message and do not
echo caller-supplied values.

Validation is not authorization. A valid organization ID does not prove the
caller may read that organization's Unit. A future caller must first authorize
the user and retrieve only the Unit and related facts they are permitted to
access. The engine preserves the organization and Unit identifiers it receives;
it does not look up, infer, or cross-check ownership itself.

## 7. How BOWERA calculates risk

The three illustrative indicators are:

| Rule | Points | Condition |
| --- | ---: | --- |
| `unit.vacant` | 40 | `isVacant` is `true` |
| `lease.expiring_within_90_days` | 30 | A known lease expiry is 0 through 90 days away, inclusive |
| `maintenance.outstanding` | 20 | `hasOutstandingMaintenance` is `true` |

The maximum is 90. Scores 0–29 are Low, 30–59 Medium, and 60–90 High. These
weights and bands are illustrative only and have not been validated as property
investment standards.

An unknown vacancy state, lease expiry, or maintenance state (`null`) does not
trigger its rule and is listed in `dataCompleteness.missingFields`. An
already-expired lease is reported in `expiredLeaseDays` and is not scored by the
forthcoming-expiry rule. It needs a separate policy decision in a future
version.

The current Unit Registry stores a Unit's active/inactive status, but that is
not an occupancy status; it does not store vacancy, lease expiry, or
maintenance issues. This milestone does not create sample customer records,
infer these values, or change the database. A service can later retrieve those
facts through the provider interfaces in `ports.ts`, then build a `RiskInput`
from verified sources. Until then, only explicitly supplied inputs can be
assessed.

## 8. Why an LLM should not calculate authoritative values

A language model can produce useful wording, but its responses can vary and may
contain mistakes. It should not determine authoritative financial, legal, or
compliance values. Those values should come from versioned rules and validated
data, with tests that check the result. A future LLM explanation provider may
summarize an already-computed assessment for a person; it must not alter the
score, priority, triggered rules, or source facts.

## 9. How automated tests prove behaviour

The tests in [`risk-engine.test.ts`](../../tests/intelligence/risk-engine.test.ts)
exercise each rule on its own, combinations, missing and expired lease data,
invalid values, stable identifiers, deterministic evaluation, and input
immutability. They use clearly synthetic UUIDs and timestamps. They do not call
a network, live service, database, or language model.

Tests do not prove that weights are commercially correct. They prove that the
code follows its stated policy consistently; product and domain experts must
still validate whether that policy is appropriate.

## 10. How this connects to future microservices

`ports.ts` defines future-facing contracts:

- `OccupancyDataProvider`, `LeaseDataProvider`, and
  `MaintenanceDataProvider` describe retrieval of their respective facts for a
  specific organization, Unit, and evaluation time.
- `RiskDataProvider` combines the three retrieval contracts.
- `PropertyIntelligenceService` describes a future application service that
  returns an assessment.
- `LLMExplanationProvider` describes optional prose generation from an
  assessment.

These are interfaces only. There is no network client, database adapter,
service endpoint, authorization change, or LLM integration in M0.8-A. A future
service can implement the contracts and enforce authorization at its own
boundary without coupling the pure scoring function to infrastructure.

## Practical exercise

Change the example input in a local test so the Unit is occupied, the lease
expires in 45 days, and maintenance is unknown. Predict the score and list the
missing data field before running the test. Then add an assertion for both
values. Do not change the weights or treat an unknown value as false.

## Mini-test questions and answers

1. **What does `leaseExpiryDays: null` mean?**
   The lease expiry is unknown; it is not equivalent to expiring today.

2. **What is the score for a vacant Unit with known no lease expiry risk and no
   maintenance issue?**
   40 points, Medium priority.

3. **Does an expiry in 91 days trigger the 90-day rule?**
   No. The threshold is inclusive through day 90.

4. **What does the engine do with an expiry of -12 days?**
   It reports 12 expired days separately and does not add expiry points.

5. **Does a valid organization UUID authorize access to the Unit?**
   No. The service caller must authorize and scope data access before invoking
   the engine.
